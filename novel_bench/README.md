# NovelBench · 小说推演质量基准

> 一套独立于主程序运行时的评测工具：拿真实小说的"设定集 + 中断点"，让模拟器从这里接着演，
> 再把推演结果和作者真正写下的后续放在一起，用**计数指标 + 盲评**两条尺子量。
>
> English: [README.en.md](README.en.md)

> **和主程序那套判据的分工**：这里量**分数**（计数指标 + 盲评），主程序的
> `tools/verify_*.py` 量**机制还在不在**（提示词有没有真接上、解析层有没有硬闸）。
> 两边的教训统一登记在 `crew/novel_rules.py` —— **53 条**规则，每条写清
> 「现象 → **可数形状** → 落点 → 判据 → 反例法 → **试过但错的解法**」，
> 生成稿见 `developers/docs/小说质量规则.md`。**准备改文笔/连贯/时序之前先翻它**，
> 免得把上一轮已经推翻过的解法再走一遍。

---

## 1. 它解决什么问题

主程序每改一次提示词、一处调度、一段导出逻辑，都会产生同一个问题：**到底是变好了还是变坏了？**
凭手感读几段台本没有用——上一次就是这么漏掉"动作重演 61%–87%"和"四字重复率是真人 20 倍"的。

这套工具把"变好还是变坏"变成可复现的数字：

| 问题 | 这条工具的回答 |
|---|---|
| 文笔像不像人写的？ | 四字重复率、句长分布、近似复读、元标记泄漏、**太碎/憋气段**、逐项跟真人基线比 |
| 是不是在手上一遍一遍打转？ | **道具循环**（同一件东西被反复续上—耗掉），真人最大 0 次 |
| 格式有没有乱？ | **引号混用**（同一篇里 ASCII 与中文引号并存；单一样式不扣分） |
| 人物是不是各说各话？ | 盲评里的"人物成形"，加上在场人物出场率、对白占比 |
| 会不会把原著的人写崩？ | 设定一致性维度 + 禁忌词/时代错置计数 |
| 跟真正的小说差多少？ | **同一把尺子**同时量推演稿与作者原文，报"差距 gap" |
| 这次优化值不值？ | `compare` 直接给出逐用例的前后差值 |

## 2. 核心设计（三条）

1. **参考锚点，不用绝对分。**
   每个用例都拿作者写的那一段做对照，用同一份 rubric 打分。报告的头号数字是 `gap = 推演分 − 原著分`，
   而不是孤零零的 78 分——因为绝对分在不同模型、不同周次之间漂移得厉害。
2. **盲评成对比较。**
   推演稿和原文以"甲/乙"出现，顺序随机；两个顺序都选中同一段才算胜，否则记平局。
   这是抵消位置偏置最便宜的办法。
3. **评的是"小说原文"，不是"小说版本"。**
   `导出/小说版本_*.md` 自己写着"**这是素材稿，不是成稿**"，而且**故意保留**
   剧本标记（`▸ 出场`、`◇ 心声`、`**场景**`）—— 拿它评测会把"设计如此"算成
   "元标记泄漏 30 处"，系统性压低所有分数。改用 `导出/小说原文_*.md`
   （小说作家写的那一篇，没有剧本标记），顺序是：原文 → 当天故事 → 版本 → 每日落盘。
   这个口径是 2026-10-18 第一次 A/B 跑完才发现的。
3b. **计数指标兜底。**
   评审模型会累、会漂、会被长文骗；计数器不会。所以重复率、禁忌词、空拍、出场率这些
   永远同时报，任何一项恶化都能在不看评语的情况下被发现。

## 2.5 口径：给作者找灵感，不是复刻原著

> 用户原话：**"我这个软件是给作者提供创意用的，所以我不追求跟原文完全相同。
> 在合理的范围内有变化也是一个重要的功能"**。

这条决定了整个评分表。第一版违背了它（问"作为续写是否合理"、把 `gap` 当主指标、
把"新增人物"算冲突），已全部纠正：

| 项 | 现在怎么算 |
|---|---|
| `canon` 设定不崩 | 只扣**违背**（世界规则 / 时代 / 称谓 / 已知事实）；**新增人物、地点、支线不扣分** |
| `plot` 戏能立住 | 只问这一段**自己**有没有起势—转折—落点，不要求接原文 |
| **`novelty` 创意增量（0.20）** | 奖励"原著没走、但走得有道理"的路；1 = 只是换个说法复述原文 |
| `gap` | **降级**成尺子校准值，回答"这尺子对这篇严不严"，不是分数目标 |
| 盲评 | 问"哪段更值得作者拿去参考"，明写"不要因为更像原著就判它更好" |

实测只换口径、不换文本：四例均分 37 → 48，《雪国》42 → **64**、`gap` 由 −24 转 **+7**，
盲评从"4 负"变"3 平 1 负"。**旧口径在系统性压低分数。**

## 4. 覆盖范围

26 部作品、28 个用例，按四条轴交叉取样：

| 轴 | 覆盖 |
|---|---|
| 载体 | 出版 22 · 网络 4 |
| 时代 | 古典 8 · 现代 8 · 当代 6 · 网络 4 |
| 地域 | 中国 16 · 英国 4 · 美国 2 · 俄 1 · 日 2 · 拉美 1 |
| 类型 | 世情/家族、历史演义、神魔、志怪文言、讽刺、乡土抒情、底层悲剧、婚恋、武侠、仙侠、硬科幻、克苏鲁、宅斗、探险恐怖、哥特、现代主义、反乌托邦、儿童奇幻、政治奇幻、心理犯罪、推理、魔幻现实 |

具体书目与"为什么选它"写在每个 `dataset/works/*.yaml` 的 `representativeness` 字段里；
出处与取舍理由另见 `docs/sources.md`。

**数据量刻意压得很小**：全书不进库，每部只留一份约 700–1200 字的设定集、
一段 150–300 字的前情提要、一段 300–500 字的"作者后续"（公版作品可附短摘录，
在版权期内的作品一律用忠实复述，标注 `license: in_copyright_short_quote`）。
这样一次全量评测的评审成本约等于读 28 篇短篇小说，而不是 26 本书。

## 5. 快速开始

```bash
# 0) 配置评审模型（只被本工具读取）
cp novel_bench/.env.example novel_bench/.env
#    填 NB_LLM_API_KEY 与 NB_JUDGE_MODEL

# 1) 免费自检：数据集合规 + 项目能装配起来
python novel_bench/bench/cli.py check
python novel_bench/bench/cli.py smoke --preset smoke

# 2) 跑推演（花钱；4 个用例约 1.5 小时，8 拍/例）
python novel_bench/bench/cli.py run --preset smoke --ticks 8

# 3) 评审（花钱）+ 汇总（免费）
python novel_bench/bench/cli.py judge  --run results/<时间戳>
python novel_bench/bench/cli.py report --run results/<时间戳>

# 4) 优化之后，跟上一轮对比
python novel_bench/bench/cli.py run --preset smoke --run-id after-fix
python novel_bench/bench/cli.py judge --run results/after-fix
python novel_bench/bench/cli.py compare --a results/<旧> --b results/after-fix
```

推演使用的是**主程序自己的 LLM 配置**（`NovelWorldSimulator/.env`）；
评审使用的是 **`novel_bench/.env`**。两者刻意分开，免得"换了评委"看起来像"产品变好了"。

## 6. 报告怎么读

`report.md` 顶部六个数字：

| 字段 | 含义 | 怎么用 |
|---|---|---|
| `sim_mean` | 推演稿的 0–100 分 | 看趋势，不看绝对值 |
| `ref_mean` | 作者原文（同一把尺子） | 校准：如果它也不高，说明这把尺子对这篇不灵 |
| `gap_mean` | 两者之差（负=推演不如原著） | **主指标**，越接近 0 越好 |
| `win_rate` | 盲评胜率（含平局） | 20%–30% 已是很好的成绩 |
| `hygiene_mean` | 计数指标折算的卫生分 | 跌到 80 以下先查重复与元标记 |
| `verdicts` | 胜/负/平 | 平局多说明两边都还行，或评委看不出差别 |

## 6.5 思考模式与成本（2026-10 起必读）

新版 `deepseek-flash`（滚动别名）**默认先想再写**：思考按输出计费，而且和正文抢同一份
`max_tokens`。实测同一句"写 300 字小说"：

| | 耗时 | 输出 token | 其中思考 | 正文 |
|---|---|---|---|---|
| 默认（思考开） | 6.1s | 900（撞上限） | 900 | **0 字** |
| 关思考 | 1.9s | 217 | 0 | 256 字 |

对推演的影响：一次 `agent_decide` 正常 200–400 token，开着思考是 **3600–4300**，
约合每拍 0.027 元、一个故事日（1080 拍）**29 元纯思考开销**，外加每拍多 10–15 秒。

基准里怎么用：

```bash
# 同一用例、同样拍数，只差思考模式（只影响这一轮，不改 .env）
python novel_bench/bench/cli.py run --case ltxz-01 --ticks 6 --think-mode auto --run-id ab-auto
python novel_bench/bench/cli.py run --case ltxz-01 --ticks 6 --think-mode off  --run-id ab-off
python novel_bench/bench/cli.py judge --run novel_bench/results/ab-auto
python novel_bench/bench/cli.py judge --run novel_bench/results/ab-off
python novel_bench/bench/cli.py compare --a .../ab-auto --b .../ab-off
```

`meta.json` 的 `think_mode` 记着这一轮用的是哪种；两轮**必须同模式才能互比**。
主程序侧的开关在「天问 · LLM 接入 → 没填就用这三项（全局兜底）→ 思考模式」，
`auto / off / always`，改完下一拍生效、不用重启。

## 7. 边界与诚实声明

- **不自动评估。** 工具只在你手动敲 `run` / `judge` 时才花钱；`check` / `smoke` / `report` 全免费。
- **不追求"打败原著"。** 目标是缩小差距、暴露结构性缺陷，不是让模型复刻曹雪芹。
- **原文仅供参考。** 推演出合理分歧不算错，`ground_truth.divergence_note` 里写明了哪些必须接住、哪些可以自由。
- **评审模型只是评委之一。** 报告里保留每个评委的原始分与评语（`cases/*/judge.json`），
  有疑问时以人读为准，不以模型为准。
- **版权。** 公版作品可用原文短摘录；在版权期内的作品只做情节复述，不复制原文长段，
  字段里逐条标注 `license`。数据集仅用于本地评测，不要再分发。
