# 参考与出处

这份基准不是凭空设计的。下面列清楚它借了谁的办法、为什么借、以及哪些地方刻意没借。

---

## 1. 评测方法

| 出处 | 借了什么 | 在本工具里的落点 |
|---|---|---|
| **G-Eval**（Liu et al., 2023, arXiv:2303.16634） | 用"评分表 + 思维链"让模型打分，比直接问"好不好"稳定 | `judge.RUBRIC` 的六维评分表、`defects` 必须指到具体句子 |
| **LLM-as-a-Judge / MT-Bench**（Zheng et al., 2023, arXiv:2306.05685） | 位置偏置、冗长偏置的实证与"交换顺序"的解法 | `judge.pairwise` 两个顺序都跑，方向相反才算胜 |
| **LitBench**（Fein et al., 2025, arXiv:2507.00769） | 创意写作没有标准答案；零样本评委里 Claude 系与人类偏好一致率最高（约 73%），专门训练的奖励模型约 78% | `docs/models.md` 的评委首选；"成对比较优于绝对分"的判断依据 |
| **WebNovelBench**（Lin et al., 2025, arXiv:2505.14818） | 用 4000+ 中文网络小说做"梗概→故事"评测；八个叙事维度；PCA 聚合后映射到人类作品的百分位 | 多维 rubric 的结构；"与人类作品对照"而非绝对分；中文网络文学必须单列 |
| **WritingBench**（Wu et al., 2025, arXiv:2503.05244） | 评分标准应当随任务/体裁变化，而不是一套通用尺子 | `ground_truth.divergence_note` 与 `focus` 字段：每个用例可以指定"这一场考什么" |
| **Art or Artifice?**（Chakrabarty et al., 2023, arXiv:2309.14556） | 模型能模仿形式，但难以维持"有意图的偏离"；评委容易把流畅误认为好 | 单列 `prose` 与 `engagement`，并把 `repeat_4gram` 作为独立硬指标 |
| **A Confederacy of Models**（2023, arXiv:2310.08433） | 多模型评审的互补性；单一评委的结论不稳 | 支持 `NB_JUDGE2/3`，维度取中位数 |
| **Too Long, Didn't Model**（2025, arXiv:2505.14925） | 长上下文模型在小说上的理解会随长度显著退化 | 评审输入按 `NB_JUDGE_MAX_CHARS` 截断，并在报告中记录截断；不假装能评整本 |
| **Prometheus 2**（Kim et al., 2024, arXiv:2405.01535） | 开源可定制的细粒度评委 | 若不想用闭源模型，可用 Prometheus 系本地部署替代 `NB_JUDGE_*` |

## 2. 叙事理论

用来决定"哪些维度值得测"，不直接进提示词：

- **亚里士多德《诗学》**：情节的整一性——事件之间要有必然或可然的关系。→ `plot` 维度。
- **E. M. 福斯特《小说面面观》**：扁平人物与圆形人物；"人物能不能被认出来"。→ `character` 维度。
- **米兰·昆德拉《小说的艺术》**：小说的智慧在于"发现"，而不是"回答"。→ `engagement` 与
  `divergence_note`（推演允许走岔，只要走得有道理）。
- **金圣叹评点**：读法即写法——他逐段问"这一句为何放在这里"。→ 评审要求 `defects` 指到具体句子，
  不接受"语言可以更优美"这类空话。
- **老舍《我怎样写小说》**：口语是底子，"一句是一句"。→ `prose` 里对短句与动词密度的偏好，
  也是选《骆驼祥子》的动机。

## 3. 选书原则

四条同时满足才收：

1. **代表性**：在文学史、类型史或销量上有一个"绕不过去"的位置。不看个人趣味。
2. **可抽设定集**：有清晰的人物、规则、地点，能在 1000 字内说清，且不丢失关键信息。
3. **有可切的场面**：存在"一群人同处一室/一地、彼此有张力"的段落。这是多智能体推演的主场；
   纯独白、纯议论的作品再伟大也不适合。
4. **覆盖互补**：每收一本，必须补上一个此前没有的格子（地域、时代、载体、叙事人称、类型）。

排除的：纯意识流（《尤利西斯》）、以结构实验为主（《无法称呼的人》）、
设定过于依赖长线伏笔（《沙丘》后段）、以及所有需要读完全书才能理解一个场景的作品。

## 5. 数据与版权

- 公版作品（作者逝世逾 50/70 年，或明确进入公有领域）：可附短摘录。
- 在版权期内的作品：**只做情节复述**，不复制原文长段；字段标注 `license: in_copyright_short_quote`。
- 所有材料仅用于本地评测与研究，不随程序分发；`novel_bench/` 目录在打包发布时应整体排除。

## 6. 与主程序既有判据的关系

主程序里的 `tools/verify_*.py` 守的是"代码行为对不对"（会不会崩、字段有没有读到、布局有没有溢出）。
这套基准守的是"产出好不好"，两者不重叠：

- 判据红了 ⇒ 有 bug，必须修。
- 基准分掉了 ⇒ 没 bug，但质量退化了，要查提示词/调度/预算。

前者可以自动跑、必须有反例法；后者需要花真钱跑模型，所以只在你手动触发时执行。
