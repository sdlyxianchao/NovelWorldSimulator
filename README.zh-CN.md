# 小说世界AI模拟

> ## ⚠ 先说清楚：**这不是"AI 替你写小说"的工具**
>
> 它是**小说创作辅助工具**，用它的时机只有一个 ——
> **当你卡住、不知道剧情接下来该怎么走的时候，让它把当前这个局面推演一遍**：
> 看看你笔下的这些人，在这个处境里**会怎么动、会说什么、会把事情推向哪儿**。
>
> 推演出来的**不是成稿**，是几条**你可以挑的路**。看完，往哪走由你定，字也由你写。

**一句话定位**：剧情推演器 + 设定试炼场。**不是** AI 代写，**不是** 一键成稿。

| 什么时候用它 | 它给你什么 |
|---|---|
| 写到半程，不知道下一场该发生什么 | 从当前局面往下推，摆出几条可能的走向 |
| 拿不准这个人物此刻会怎么反应 | 让他按自己的记忆、口癖和隐瞒开口、动手 |
| 想验证一条支线撑不撑得住 | 从这个节点往下推几天，看故事会不会自己崩掉 |
| 人物说话越来越不像他自己 | 把他放进不同处境里开口，反过来校准人物卡 |

> 它不替你写，也不替你决定 —— 它只负责**把局面往下走一遍**，让你有东西可以挑。

## 这是什么

**小说创作辅助工具 —— 一个在你自己设定里跑的剧情推演器。**

给它一个装着小说设定和稿子的文件夹，它会在**你的设定范围内**把故事往下推演，产出**可以改写、可以对照、可以续写**的素材。它不替你写小说，也不替你做决定——它是**素材发生器**和**设定试炼场**。

**它做什么**
- 读你的设定、大纲、人物卡、正文，提取世界观与人物
- 在设定允许的范围内推演情节，每天落盘成文
- 给出故事文档、运行小结、大纲建议，以及"如果这样走会怎样"的对照

**它不做什么**
- 不自动生成可以直接发布的成稿
- 不无限发散——默认有清晰的故事进度表和终点
- 不改写你的原稿（程序永不反写项目文件夹）

**先拿现成的试一遍**：程序目录下的 `samples/` 里有**六个题材各一篇原创示例**（悬疑 · 单元剧、玄幻修仙、都市、历史架空、言情、科幻），每篇都写了**中文和英文两个版本**。开卷时选中**其中一篇那一层**（例如 `samples/zh/01_悬疑单元_更漏子/`）就能跑 —— 别选 `samples/` 或 `samples/zh/`，那样六篇会被当成一本书。清单见[使用说明 §6.1](使用说明.md)。

这六篇是**按黄金档写全的范例**，不是占位文件：大纲都加厚到 **3400 字以上**，中英两版逐站对齐，每一站都写了「完成判据 / 高潮 / 情节线」三样，另加一节「悬念的次序」和一套「幽默纪律」。详细清单见 [`samples/README.md`](samples/README.md)。

上面这段是**一次真实运行的完整流程**，没有剪辑、没有摆拍 —— 启动画面 → 开始界面 → 拾卷选题 → 起笔 → 中栏一天天累积 → 查看地图 → 点停止 → 收尾 → 导出结果。约 35 秒（原始 47 张截图按时间顺序合成，`使用说明.md` 里有每一步的文字说明）。

几处值得留意的：

- **中栏不是一次性刷出来的**，而是一拍一拍往下长；右边「剧组 Agents」那一栏是**谁在出工**，出工中与已交活是同一行的两个状态。
- **停止之后还要等几十秒到几分钟**：收尾要跑 场记 → 宣发 → 审校 → 复盘 → 整理 → 导出 一串调用。这不是卡住。
- 最后那张**地图**是这天的世界状态，不是示意图。

## 你能拿到什么

推演跑完（或随时中断），项目文件夹里会有：

| 产出 | 内容 | 你可以怎么用 |
|------|------|-------------|
| **每天的叙事** | 按故事日切分的完整叙事文本 | 挑可用的段落改写进正文 |
| **故事文档** | 时间轴 / 关键场景 / 精彩情节 / 人物弧线 / 伏笔状态 | 通读一遍找灵感、核对伏笔有没有埋漏 |
| **运行小结** | 运行概览 / 故事线 / 关键情节 / 人物表现 / 优化建议 | 复盘"这版推演哪里走偏了" |
| **大纲建议** | 节点对照表 / 新增支线 / 伏笔更新 / 后续建议 | 反哺你自己的大纲 |
| **完整设定集** | 打包好的世界观 + 人物 + 进度 + 风格卡 | 换工具/换机器时带走，或作为设定存档 |
| **关键事件清单** | 每次事件的时间、类型、涉及人物 | 快速定位"哪一天出了什么事" |
| **快照** | 任意时刻的完整世界状态 | 回到某个节点，换一种走法再推一遍 |

> 对写作者最实用的用法，是**同一段设定推演两三遍，拿几版结果做废案对照**——比对着看，往往能挑出自己原稿里没想到的那条路。

## 它和"AI 写作工具"的区别

这不是一个"帮我把这段写出来"的工具。它**跑一个世界**，小说是读轨迹的结果。

| | 普通 AI 写作工具 | 这个 |
|---|---|---|
| 你给什么 | 大纲、章节要求 | **初始条件**（谁、要什么、缺什么、世界怎么运转） |
| 它产出什么 | 你要的那段字 | 一条**轨迹**；小说是读轨迹的副产品 |
| 什么算好 | 符合你的预期 | **自洽且意外**——你会说"我没料到，但确实该这样" |
| 多次运行 | 越改越像你要的 | **每次不一样，但每次站得住** |
| 你控制哪一层 | 情节 | **因果律**，不控制具体事件 |

### 两个自由度旋钮（`TASK_FREEDOM` / `STYLE_FREEDOM`）

起笔对话框里可调，`.env` 里也能改，默认都是 50。

| 旋钮 | 0–34 | 35–64 | 65–100 | 放开后的代价 |
|---|---|---|---|---|
| **任务规训** | 照剧本演（剧本 + 分拍表都给，温度 0.55） | 只给要办的事（不给分拍表，温度 0.75） | 只给议程（温度 0.91） | 剧情会散，可能跑题、可能空转 |
| **文笔规训** | 很讲究（禁词全列/距离强制/思维链五问/口癖配额） | 标准（禁词约 3/4） | 松（禁词一半/距离自选/思维链一问/**口癖配额关**） | 可能出现难看的句子；口癖会回弹 |

**为什么是两个**：一个旋钮同时管这两件事，会逼出两种坏结果之一——
想要意外就顺手把文笔也松了（更散**且**更难看），或者想保住文笔就再也不松任务（回到照剧本演）。

**想要"每次不一样"就调任务规训**（这是唯一能改变"发生什么"的）。想知道到底多不一样，
用 `tools/probe_divergence.py` 量——它看的是**骨架重合**（谁·做了什么类型的事），
不是文字重合。实测《雪国》跑两次：文字 9.7%，**骨架 62.5%** ⇒ 半发散（人换了、事没换）。

### 世界法则：事件不是被"设计"出来的

四条压力，纯代码算、零模型调用：**目标冲突**（两人盯同一件事）/ **处境恶化**（体力、情绪、坏事）/
**秘密压力**（藏了多久 + 有人逼近）/ **时间压力**（一天过了多少、还剩几拍）。

**事件类型 = 压力最大的那一条破掉。** 代码定类型，模型只写具体内容，理由来自压力证据。

四条都低时**这一拍不出事**（连模型都不调）——这是"日常生活型"的开关。
没有它，就退化成"每 8 拍必须出点事"，跟改之前没区别。

> 写作是"我要这个效果，所以安排这个事件"；
> 推演是"这个局面必然导致这个事件"。

完整说明见 `使用说明.md` 的 §4.20（两个旋钮）与 §4.21（世界法则）。

## 典型写作场景

下面这些，都是"不知道该怎么往下写"的时刻 —— 也就是这个工具该出场的时候：

**1. 卡在中间写不下去**
把已有的正文和设定丢进去，让它从最新进度往下推。它给的不一定是你要的那条路，但通常能给你三条你没想过的路。

**2. 人物「说话不像」**
推演里每个人物有自己的记忆、口癖、计划和隐瞒。看它在不同场景下怎么开口，反过来校准你的人物卡。

**3. 验证情节逻辑**
"如果主角这时候就摊牌，后面还撑得住吗？" 让它在这个节点往下推 3 天，看故事会不会崩。

**4. 补细节和场景**
你只有大纲没有血肉？让它把大纲节点填成有对话、有动作、有心理的段落。

**5. 试不同写法**
用项目设置里的风格控制（虐心 / 幽默 / 爽点 / 悬念 / 节奏），同一段设定换一组参数跑，对比哪种调性更合适。

## 特性清单

- **读得进**：自动读 .md / .txt / .docx / .html，提设定、判类型、提取风格、对齐正文进度
- **走得完**：默认 `story` 模式，有故事进度表和终点判定，走完自动收尾出小结
- **接得上**：有正文则默认接续最新进度；只有大纲则任选节点起手
- **贴得住**：导演引擎装载叙事工艺库（西方编剧正典 / 中国古典章法 / 网络文学方法论），按类型取用冲突设置法和节奏模板
- **控得住**：风格控制面板实时显示并可调——虐心、幽默、爽点密度、感情线、悬念、人物智商、节奏
- **放得开**：两个**互不影响**的自由度旋钮——**任务规训**（人物能自己决定干什么：照剧本演 → 只给要办的事 → 只给议程）与**文笔规训**（字有多讲究：禁词列多少、距离强不强制、思维链几问、口癖管不管）。⚠「不许替别人说话」这两个旋钮都碰不到——那是世界的物理法则，不是规训
- **说得清**：导演不是编剧。每 8 拍不再问模型「设计一个戏剧事件」（那个问法会自动收窄到最安全的那类），而是**算出四股压力**（目标冲突 / 处境恶化 / 秘密压力 / 时间压力），让最大的那条**自己破**。事件类型由代码定、理由来自压力证据，模型只负责把它写成一件具体的事
- **看得清**：叙事按**剧本式**输出——分幕、分条目（时间/场景/出场退场/旁白/对白/动作/心声），**同一条时刻多人在做不同事会排成「同时」的并行轨**，异地同时用「切至」；每幕标「本幕依据」（推进哪个节点、回收哪条伏笔），可读也可审计
- **录得全**：每天叙事落盘；随时一条命令出故事文档、大纲建议、运行小结
- **退得回**：快照回溯，可回到任意节点换一种走法
- **省得起**：Token 硬预算 + 降级阶梯 + 每日账单
- **守得严**：独立合规检测（本地策略库 + LLM 复核 + 可选外部服务）
- **查得准**：遇到设定外的知识（官制、律法、时辰、路程）走考据通道——先查内置技能库（8 个离线知识包）和 MCP 服务（3 个本地只读查询服务），都不中才联网或问 LLM；**越靠前越便宜可靠**

## 外部创作服务（可选增强）

程序旁边可以挂三座**独立的创作服务**（都在 `novelservices/`，都是**可选**：不起也不影响推演）：

| 服务 | 干什么 | 谁来用 | 端口在哪 |
|------|--------|--------|----------|
| **MuMuAINovel** | 写小说正文（样章 / 导出重写） | 小说作家 | 它自己的 `backend/.env`（默认 8001） |
| **PlotPilot（墨枢）** | 叙事引擎：这一章该发生什么 | 剧作者 | **主程序根** `.env`（默认 8005） |
| **PenShot** | 导演 / 分镜引擎：这一场怎么拍 | 导演 | **主程序根** `.env`（默认 8000） |

- **配置 / 起停**：开始界面 →「天机」→「外部创作服务」页。三段各有总开关、「谁来用」、
  **程序启动时自动拉起服务**、**关闭程序时一并停掉服务**，以及「启动 / 停止」按钮和实时状态。
- **端口归 setup 管**：安装时检查本机端口（机器上跑着 Docker 也没关系），被别的程序占着就
  从原端口往上找一个**能用的**，写回该服务读的那份 `.env`；如果是服务自己占着（健康检查通）就不动。
  查当前实际端口：`start.exe --selftest 报告.json`（每个服务都有 `port` / `port_busy`）。
- **失败自动退回**：服务没起 / 超时 / 写空，对应职位会退回本程序自己的写法，并把降级原因记在产出上。
- 发布包**不含** `novelservices/`（体积大、各有各的许可）—— 用户机上三座都缺席是**被支持的常态**。

## 开始界面（八个入口）

启动后先看到一块**中国水墨丹青**的标题屏，不是直接进编辑器：

```
                    [ Logo ]
              小 说 世 界 A I 模 拟
              ── 把 故 事 ， 活 一 遍 ──
                 当前项目 【书名】

                   开　卷   导入小说文件夹
                   拾　卷   打开以前的故事
                   起　笔   开始推演一轮
                   拆　书   读一本好书，学写法
                   天　机   程序设置：模型、预算
                   书　斋   本书设置：类型、风格
                   回　卷   回到推演界面
                   归　去   退出程序

              v0.3.3 · 本地运行 · Python + Flet
```

| 入口 | 小字 | 做什么 | 没项目时 |
|---|---|---|---|
| **开卷** | 导入小说文件夹 | 四步导入向导，把新小说读进来 | 可点 |
| **拾卷** | 打开以前的故事 | 打开以前做过的书 | 灰掉 |
| **起笔** | 开始推演一轮 | 定本轮参数，开演 | 灰掉 |
| **拆书** | 读一本好书，学写法 | 把好书的写法拆进技能库 | 可点 |
| **天机** | 程序设置：模型、预算 | **全局**设置，换哪本书都生效 | 可点 |
| **书斋** | 本书设置：类型、风格 | **只对当前这本书**生效 | 灰掉 |
| **回卷** | 回到推演界面 | 跳回运行界面 | 灰掉 |
| **归去** | 退出程序 | 关掉软件 | 可点 |

> **顺序是「先找书、再动笔」**：开卷（新书）→ 拾卷（旧书）→ 起笔（开演）。
> **天机管程序、书斋管本书** —— 这两个名字最容易混，小字直接点破了。

**键盘**：`↑` `↓` 选，`Enter` 确认，`Esc` 回到运行中的故事。

**启动时消息框**会报一件事：能力校验的结果（模型声明与实际不符时会说「已改回」、
「需要重启」、「演示模式」）。**那是说明，不是报错** —— 看到「需要重启」就真重启一次。

## 快速开始

### 1. 安装并启动（一条命令）

**不用懂 Python，双击就行。**

| 系统 | 操作 |
|------|------|
| **Windows** | 双击根目录的 **`start.exe`** |
| **macOS** | 在访达里双击 **`start`**（或在终端执行 `./start`） |
| **Linux** | 终端执行 `./start` |

启动器会自动完成：找 Python → 创建独立运行环境（`.venv`）→ 装依赖 → 启动程序。

> 启动时会先出现一块**「书封」启动窗口**（没有控制台，但启动过程全看得见）：Logo / 名字 /
> 「把故事，活一遍」，下面一行**滚动的启动消息**；点消息条右边那个 **`›` 折线箭头**
> 可展开成**命令行输出**（执行的命令、报错原文都在里面，失败时那一步会标红并停下来），
> 再点一次箭头转成 **`⌄`** 收起。底栏固定是 `v0.3.3 · 本地运行 · Python + Flet`，
> 右上角 **✕** 随时可关；程序窗口出来后它自己消失。
>
> 展开后那块日志区是 **14 行 / 218px**（2026-10-27 起，之前只有 7 行）：
> 里面是**每一家服务拉起来的全过程**（建环境、装依赖、起端口、健康检查），
> 三家合在同一条流里，每行以 **`[时间][服务]`** 开头 —— 一眼看得出这行是谁说的；
> 没有这个前缀的那些行是启动器自己写的（版本、平台、准备运行环境）。
> 程序自己在启动期说的 WARNING / ERROR 也写进来（`[时间][程序]`），
> 所以"卡在哪一步"不用去翻文件。
> ⚠ **消息条只显示进度**（那几句带 `→` 的），服务的一行普通输出不会顶掉它 ——
>   否则 uvicorn 日志里的一个 `ERROR` 就会让"正在启动"读成"启动失败"。
>
> **失败时原因只出现一次**：消息条改成一句中性的"启动没成功"，原因写在它下面
> **那行居中的红字**上（整幅宽，长原因自动折成两行，不会把"点右上角 ✕ 仍然进入"
> 那半句截掉）。以前同一句话被画在消息条和那行红字两处，收起态它们只差 42px，
> 看起来就是"错误信息有两条"。
>
> 收起时窗口只有 **860×350**（展开 860×602）—— 只占屏幕中间一小块，不挡你看的东西。

> ⚠ **三个启动器是按平台分别编译的**（Go，交叉编译），根目录里那一套**只给本机平台**。
> **一个发布包带四个平台**：根目录是本机那套，其余三套在 `启动器/其他平台/<平台>/` 里
> （换系统时把对应目录那三个文件拷到包根目录即可）。包内 `平台说明.md` 写明各套落在哪。

<summary>发布包怎么打（一个版本一个文件夹，四平台全带）</summary>

```bash
python tools/make_release.py                            # → 发布版本/0.3.3/
```

脚本做八件事：新建版本文件夹 → 整棵复制（排除表在复制前生效）→ 四套启动器各就各位 →
重新生成 `.env` / `.env.example` → 同步本机 `.env` 里未登记的键 → 清空样例里的密钥与
LLM 配置 → 兜底清扫日志/缓存/台账/开发目录/旧备份 → 自检（拿**真实密钥**全文搜、查
`sk-…` 字面量、本机路径、残留日志与数据库、必带文件、四套启动器魔数）。
版本号只有 `config.py` 的 `VERSION` 一个来源。

打包与自检都会**读启动器的魔数**核对平台（Windows 是 `MZ`、Linux 是 `ELF`、macOS 是 Mach-O
并按 cputype 分 arm64 / x86_64）—— 文件名判不出来（Linux 与 macOS 都叫 `setup`），
魔数才说了算。

## 用脚本驱动（Python SDK / 命令行）

界面能做的事，脚本都能做 —— **同一份实现**，只是换了个壳。适合：批量跑、
定时任务、服务器上无人值守、把推演接进你自己的流程。SDK **不依赖界面**
（整个 `nws` 包不 import flet），可以在没有桌面的机器上跑。

### Python SDK

```python
import sys
sys.path.insert(0, r"<项目目录>\developers\sdk")     # 只需要这一行
import nws

nws.config.set(MOCK_LLM=True)                      # 演示模式：零成本、零网络
book = nws.project.create("演示书", source=r"C:\素材\演示")   # 建书（登记素材）
nws.ingest.run(book)                               # 开卷：读素材 → 冻结设定集
r = nws.run.start(book, days=1, max_ticks=6)       # 起笔：推演
r.wait()
nws.export.run(book, r.run, kinds=["novel", "report"])
print(r.snapshot(), nws.usage.summary(book.name))
```

九个模块，覆盖你点名的那几件事：

| 模块 | 管什么 |
|------|--------|
| `nws.config` | **全局设置**（29 组 SPEC，读写 `.env`；`temporary()` 改完自动还原） |
| `nws.project` | **项目**：建 / 找 / 打开 / 列出 / 删（搬到「已删除备份」，可恢复）/ **项目设置** |
| `nws.ingest` | **开卷**：`plan()` 先看要发出去多少字，`run()` 真跑，`gate=` 同意门 |
| `nws.run` | **起笔 / 推演**：起 / 暂停 / 继续 / 停 / 快照 / 选岔路 / 续跑 |
| `nws.archive` | **存档**：某轮的副本（快照语义） |
| `nws.export` | **报告导出**：五种产物（两种要调模型），版本自增不覆盖 |
| `nws.usage` | **用量报表**：次数 / token / 费用，按模型·日期·模块·推演任务拆 |
| `nws.mumu` | 可选的 **MuMuAINovel** 写小说服务（状态 / 启停 / 生成 / 润色） |
| `nws.aio` | 异步外观（Jupyter / FastAPI / Flet 里用） |

- **完整 API 参考** → `developers/sdk/API.md`（源码树里，不随发布包提供）
- **八个可直接跑的示例** → `developers/sdk/samples/`（源码树里，不随发布包提供）

### 命令行

```bash
python -m nws list                     # 有哪些书
python -m nws info 示例书               # 这本书什么状态
python -m nws ingest 示例书 --plan       # 只看要发出去多少（不发请求、不花钱）
python -m nws run 示例书 --days 1 --ticks 6 --follow
python -m nws export 示例书 --kinds novel,report
python -m nws usage --scope 示例书 --by 模型
python -m nws mumu status
```

⚠ **危险 / 花钱的动作要 `--yes`**（删书、开卷），否则只打印"将要做什么"。

**两条纪律**（脚本里尤其重要）：SDK **不写你的 `.env`**（要落盘得显式
`save()`），也**不碰引用文件夹**；「删除」一律是**搬到「已删除备份」**，可恢复。
（`tools/verify_sdk.py` 的 70 项判据里有两条专门自证这件事：跑完比对 `.env` 的
sha1 与真实 `Projects/` 的条目数。）

### 一条命令跑「任意素材文件夹」（无人值守）

`novel_bench` 只吃数据集里写死的用例；想量"**这次改动放到 `samples/` 或我自己的
项目里，东西是不是变好了**"，走这一条（源码树里的 `developers/run_input_folder.py`，
**不随发布包提供**；发布包里等价操作是界面上的 开卷 → 起笔）：

```bash
./.venv/Scripts/python.exe developers/run_input_folder.py \
    --src "samples/zh/06_科幻_回声站" --name "回声站" --ticks 6 --run-id test-echo
```

它和界面走**同一条路、同一批函数**（开卷 → 建项目 → 装配 → 跑 N 拍），产物有
`novel.md`（当天故事）/ `transcript.md`（逐条实录）/ `summary.md`（推演小结，含
审读改写了几条、为什么）/ `project/`（项目目录，可拷回去用界面接着跑）。

常用参数：`--ticks N` 拍数、`--cast 甲,乙` 限定上场、`--scene` 锁场景、
`--clock HH:MM` 起始时间、`--no-ingest` 把 `--src` 直接当已提炼的设定集、
`--resummarize <产物目录>` **只重写小结**（不重跑、不花钱）。

跑完几例想合在一起看，用 `developers/make_test_report.py <目录…>`，
它出一张总表（字数 / 审读改写数 / 推演分 / 原著分 / 盲评）+ 各例小结与正文。
细节与耗时见 `使用说明.md` 的 **5.8.4**。

## 技术栈

- **语言**：Python 3.10+
- **界面**：Flet 1.0（桌面 GUI，水墨丹青画风）
- **LLM**：OpenAI 兼容协议（默认 DeepSeek，可换混元 Hy3 / OpenAI / Claude / 通义千问 /
  智谱 GLM / Kimi / MiniMax / 本地 Ollama）
- **多模型**（2026-10-12 起）：**一个程序里可以同时配多家**，每条模型自带地址与密钥；
  「模型与LLM」页管"配哪些模型"，每个 Agent 在「剧组 Agents」里**各自指定用哪个** ——
  写小说用一家、判定用另一家都行。页面上还有一张**推荐表**（哪个功能推荐用什么模型）
- **费用看得清 + 能省**（2026-10-12 起）：「用量报表」按**模型**列出费用与 token 数，
  并给出每个模型的**缓存命中率**与**缓存省下的钱**；每条模型可以按自己的账单填单价。
  省钱四招（模型分级 / 前缀缓存 / 同题复用 / 挑空闲时段）见 **《省钱指南.md》**
- **存储**：SQLite + 文件（Markdown / YAML / JSON）
- **依赖**：flet、Pillow、pyyaml、python-docx、chardet、httpx
